# Общие компоненты

Здесь команды делятся своими интеграциями и инструментами. Выберите то, что поможет проверить вашу гипотезу. Например, один и тот же погодный модуль может пригодиться нескольким командам, даже если они строят маршруты по-разному.

- [Мониторинг зимней обстановки `kamchatka-cam`](kamchatka-cam/README.md) от Eazyan. Камеры, прогноз и локальное демо.
- **Карта и маршрутизация.** Возьмите участки и координаты из OpenStreetMap. Для времени переездов можно использовать OSRM. Заполняйте `transit_seconds` в секундах и в исходном порядке точек. Если допустимого переезда нет, пишите `null`. Укажите источник, профиль транспорта и время выгрузки.
- **Погода.** Возьмите почасовой прогноз для района, например из Open-Meteo. Покажите, по какому правилу он меняет работы смены. Например, обновите `work_seconds` по вашей оценке скорости уборки. Если добавляете повторный проход по магистрали, задайте отдельную работу и учтите нужное время её начала в планировщике команды. Укажите часовой пояс, время прогноза и единицы измерения.
- **Полевые данные.** Сохраните ширину проезда, ограничения техники или фактическое время расчистки в формате, который другая команда сможет воспроизвести. Для критического проезда перечислите в `access_jobs` все участки, необходимые для его открытия.

Предлагайте компонент отдельным PR. Подпишите команду-автора, добавьте команду запуска, пример результата и укажите, нужны ли сеть или ключи. Для интеграции приложите маленький пример данных, пригодный для проверки без сети. Ключи храните вне репозитория. При заимствовании укажите авторов в описании команды.

Выход интеграции можно сохранить в копию `scenarios/district.json` и передать в общий запуск через `--data`. Команды сами решают, какие общие компоненты брать.
