# Проверки для Codex — release gate

## Есть сейчас

```bash
npm run check
npm test
npm start
```

Внутри первые 11 тестов для `routing` и `optimizer`; дополнительные проверить программно и через браузер. Результаты старта на OSM графе 20.11.2026: baseline 168.779 км, 26 рейсов, 0 м³ нераспределённого снега; кандидат C — 101.829 км/25 рейсов; кандидат D — 110.286 км/25 рейсов. **С 21.11.2026 (v4.1) демо-сценарий изменён (узлы D1, D3, D5 больше не совпадают с площадками, нулевых рейсов нет): baseline 167.098 км / 26 рейсов; C 108.556 км / 25; D 122.648 км / 25; везде 0 м³ не распределено.** Это **контрольные синтетические значения именно этого solver и сценария**, не исторические данные города, и могут измениться при сознательной замене алгоритма.

## MUST HAVE — формальные тесты

- [ ] A01: входной graph имеет ожидаемые версию и число узлов/рёбер, SHA не меняется незаметно.
- [ ] A02: одностороннее ребро даёт разную доступность или длину туда и назад.
- [ ] A03: закрытое ребро исключено из маршрута в обе стороны, при отсутствии объезда `path=null`.
- [ ] A04: `routable=false` не используется в пути.
- [ ] A05: для каждого demand `sum assigned + unserved == D_i`.
- [ ] A06: для каждой площадки `sum received <= capacity`.
- [ ] A07: для рейса `amount <= bodyM3` и `amount * density <= payloadKg` при известных величинах.
- [ ] A08: расстояние рейса = directed outward + directed return; нет решения «туда есть, назад нет».
- [ ] A09: разные сценарии сравниваются на одинаковых базовых данных; solver не мутирует вход.
- [ ] A10: при дефиците ёмкости не скрывать `unservedM3`, приоритет ranking — минимальный остаток.
- [ ] A11: `baselineKm == 0` не порождает Infinity/NaN в %.
- [ ] A12: отсутствует реальная площадка — ни один статус не автоматически `approved` или `verified`.
- [ ] A13: подмена `legalStatus:'verified'` в JSON НЕ превращает кандидата в одобренный юридически.
- [ ] A14: вход с несуществующим узлом и отрицательной ёмкостью отклоняется без 500.
- [ ] A15: 3 повторных вычисления одного входа дают одинаковые результаты.
- [ ] A16: маленький exact oracle обнаруживает хотя бы один контрпример к жадной эвристике.
- [ ] A17: импорт содержит некорректный JSON — UI показывает ошибку, не уничтожая предыдущий сценарий.
- [ ] A18: карта визуально отличает спрос, базовые площадки и кандидаты.
- [ ] A19: клиент не исполняет HTML из пользовательских названий/JSON.
- [ ] A20: API доступен только localhost по умолчанию; статический сервер не отдаёт пути вне `public/`.
- [ ] A21: лицензии Leaflet/OSM/Mapzen и attribution показаны и сохранены.
- [ ] A22: `npm test`, `npm run check` и проверка браузера доступны без CDN и API-ключа.

## Проведение демо за 3 минуты

1. Открыть карту, сказать «все точки и числовые параметры искусственные; дороги — реальная геометрия OSM».
2. Показать 5 источников, 2 базовые площадки, 2 альтернативы.
3. Запустить сравнение и выделить необслуженный объём/пробег/рейсы; переключить вариант с отображением путей на карте.
4. Изменить вместимость кандидата до нуля и объяснить влияние ограничения.
5. Скачать JSON; показать, что результат воспроизводим из того же сценария.
6. Сказать «географическая и санитарная пригодность не проверена».

**Не проходит release gate**, если приложение предлагает пользоваться теоретическим кандидатом как разрешённым полигоном или скрывает недоставленный снег, чтобы улучшить метрику километров.
