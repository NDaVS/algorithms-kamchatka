# Планировщик и показ реагирования

## Запуск

Пилотные расчёты доступны в [интерфейсе](../demo/index.html) при открытии файла. Для расчёта в реальном времени и общей SQLite-базы запустите из корня проекта Python 3.12 или новее.

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-core.txt
python workspace_server.py
```

Откройте адрес из первой строки терминала. При запуске командой выше это [127.0.0.1:8765](http://127.0.0.1:8765/). Оставьте сервер работать в терминале. Сообщение «Для городского сценария запустите сервер расчёта» означает, что вкладка открыта в офлайн-режиме. Перейдите на адрес сервера в новой вкладке. Локальные смены офлайн-режима и смены в SQLite хранятся отдельно.

### Как показать город

1. Откройте **ДЕМО**, выберите **Город · 300 участков** и нажмите **Пересчитать B0 и O1**. Когда появятся цифры в таблице и над картой будет указано «Расчёт ядра · 300 направленных участков», планы готовы.
2. Переключайте **B0** и **O1** над картой, чтобы увидеть маршруты выбранного варианта. Голубым показаны запланированные рабочие проходы, зелёным — уже выполненные, красным — участки с пропусками. Кнопка с прицелом возвращает обзор всего плана.
3. Нажмите **Запустить показ**, чтобы машины начали выполнять маршруты. С включёнными **Случайными событиями** новые задачи появляются по времени симуляции. **Событие сейчас** добавляет задачу сразу и запускает показ. Янтарным отмечены событие и маршрут реагирования. **Сначала** сбрасывает время и события, сохраняя рассчитанный план.
4. Чтобы перенести выбранный B0 или O1 в диспетчерскую, нажмите **Принять в новую смену**, затем **Запустить смену**. В этой смене действуют обычные операции диспетчерской, включая приёмку завершённых маршрутов. События резерва остаются во вкладке показа.

Для показа работы при нехватке времени выберите **Короткая смена** и раскройте список участков с пропущенными проходами. Сценарии **Снегопад · пилотный район** и **Короткая смена** можно проиграть из файла с сохранёнными расчётами.

## Путь данных

1. [Адаптер](../planning_bridge.py) формирует один снимок для B0 и O1. B0 использует жадную эвристику. O1 выбирает сочетание из пула допустимых маршрутов с помощью SciPy MILP/HiGHS. Оба результата проходят независимую проверку SnowOps и оценку по одному тарифу.
2. `GET /api/plans?case=base_snowfall&seed=42` возвращает версию графа, хеш входа, парк, направленные задачи, действия и метрики. Разрешённые сценарии: `base_snowfall`, `short_shift`, `city_300`. Допустимый seed: целое от 0 до 2 147 483 647. Ответ 409 обозначает занятый расчёт, 503 — отсутствие зависимостей. Частичный план содержит список пропусков и их число. Структурно некорректные результаты отклоняются до передачи в интерфейс. Адаптер хранит графы в памяти процесса. Один расчёт выполняется одновременно.
3. [Экран показа](../demo/demo-plans.js) использует координаты ядра для планов и локальный слой OSM для фона. В маршруте сохраняются четыре режима `d` (переезд), `s` (рабочий проход), `w` (ожидание), `r` (возврат), отметки начала и конца в секундах, узлы, линии OSM и ID заданий. [core-pilot.js](../demo/core-pilot.js) содержит результаты тех же расчётов, seed 42, для автономного показа. Сохранённые результаты не включают время работы решателя.
4. При принятии плана [исполнение смены](../demo/shift.js) сохраняет его расписание и координаты, преобразует маршруты в задания на машины и сохраняет происхождение в журнале и снимке. Снимок открывается на паузе, движение возобновляется с сохранённого времени. В принятом плане в выполненную уборку входят рабочие проходы. В ручном плужном задании действует отдельное правило попутной уборки. Отметка препятствия приостанавливает маршрут принятого плана. Частичный план принимается отдельной явно подписанной кнопкой.
5. Показ событий добавляет два модельных экипажа резерва. На пригодном направленном сегменте OSM появляется случайное событие. Браузер строит A* от позиции каждого свободного экипажа с учётом направлений и доступных поворотных ограничений. Из достижимых вариантов выбирается экипаж с наименьшим сценарным временем переезда и обработки. При занятости событие ждёт. При завершении запасная машина остаётся в конечном узле и доступна для следующего события. После переключения вкладки показ ставится на паузу. Резерв и события существуют только в памяти вкладки.

## Что означают результаты

Геометрия дорог происходит из OpenStreetMap, [атрибуция и лицензия ODbL](https://www.openstreetmap.org/copyright). В [манифестах снапшотов](../data/pkc/) сохранены источники, границы и хеши загрузок. Карта диспетчерской и сеть планировщика могут отличаться. Слой плана использует собственную геометрию, а реагирование доступно на участках с маршрутом в локальном графе.

Парк, тарифы, сроки, движение и события моделируются. Сравнение затрат относится к входному сценарию. Полевой GPS, перепланирование оставшейся смены из текущего состояния, снежная модель, вывоз и реальные диспетчерские интеграции остаются отдельными этапами. Эксплуатационное развёртывание описано в [WORKSPACE.md](WORKSPACE.md).

Из каталога коллег перенесены модули `snowops`, нужные B0/O1 и встроенному CLI, два OSM-снимка с манифестами и политика инфраструктуры. Внешние эксперименты CARP и модель снега остаются в исходном архиве.
