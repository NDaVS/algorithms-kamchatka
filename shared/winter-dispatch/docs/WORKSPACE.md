# Рабочее место диспетчера

Оболочка покрывает ручную смену от создания до приёмки и архива. Карта использует локальный снимок OSM. Для движения используется текущая модель телеметрии, ручные назначения и существующий расчёт пути. Оболочка работает независимо от Python-планировщика.

## Запуск

- Локальный режим. Открыть [диспетчерскую](../demo/index.html) или отдать каталог `demo` простым HTTP-сервером. Смены сохраняются в хранилище браузера. При первом запуске обновлённой версии сохранённая смена v1 переносится без удаления исходной записи.
- Общая база. Из корня проекта запустить `python3 workspace_server.py` и открыть `http://127.0.0.1:8765/`. Сервер хранит смены в `runtime/shifts.sqlite3`. Порт и файл задаются флагами `--port` и `--db`. Клиенты открывают один адрес сервера. Для сети вне этого компьютера параметр `--bind` выбирается администратором. Текущий сервер предназначен для локального запуска или доверенной тестовой сети.

## Ручной цикл

1. В «Сменах» указать подпись оператора, затем дать новой смене название и выбрать парк. Новая смена создаётся без заданий.
2. В «Парке» включить или снять машину. На активном проходе снять её можно после передачи или отмены задания. Для новой машины указать номер, тип и одну из стартовых точек на карте. Парк хранится в смене.
3. Выбрать участки на карте и дать задание. В карточке можно изменить приоритет, передать работу свободной машине или отменить назначение с указанием причины. Передача сохраняет предыдущий проход и создаёт связанное назначение на оставшиеся участки. Частично выполненный участок новая машина проходит с начала. Освободившаяся машина остаётся в своей точке и начинает следующий переезд из неё.
4. После выполнения прохода статус становится «На приёмке». Диспетчер явно принимает работу, при необходимости добавляет комментарий. Смену можно закрыть после приёмки или отмены всех открытых заданий.
5. Открыть закрытую смену из истории. Её карточки, парк, карта и журнал доступны для чтения. «Выгрузить журнал» сохраняет полный JSON с заданиями, парком, статусом, временем, комментариями и подписями оператора.

Чтобы увидеть новую версию записи, откройте смену заново из истории. В общей базе запись проверяется по ревизии. Если другая сессия уже сохранила изменения, сервер возвращает конфликт и останавливает локальное воспроизведение в устаревшей сессии. Записанные события можно только дополнять, закрытая смена неизменяема. Подпись — ввод оператора, пока без подтверждённой личности и разделения полномочий.

Если видимая линия не подходит для задания, клик показывает причину, класс и ссылку на объект OSM. Класс `highway=track` исключён текущим правилом допуска. Это ограничение профиля, а возможность проезда конкретной машины требует данных о дороге.

## Контракт для переезда

- `demo/workspace-store.js` определяет операции `list`, `read`, `write`. У них два адаптера, браузерный и HTTP. Интерфейс передаёт версионированный снимок смены. Движение и планировщик используют свои входы.
- `GET /api/shifts` возвращает историю. `GET /api/shifts/{id}` возвращает `{revision, snapshot}`. `PUT /api/shifts/{id}` записывает снимок с заголовком `If-Match`. Значение `0` создаёт запись, `409` означает устаревшую ревизию, закрытую смену или изменение уже записанного журнала. Атомарность записи обеспечивает SQLite. События хранятся в снимке от новых к старым.
- При переезде сохранить HTTP-контракт либо дать фронтенду адаптер. Перенести проверки переходов состояний и прав на сервер. Смены и журнал можно экспортировать из текущего хранилища и импортировать с сохранением идентификаторов. PostgreSQL подходит, если понадобятся несколько экземпляров серверного приложения и более гибкий доступ к данным. SQLite подходит для ограниченного пилота в доверенном контуре.
- После выбора инфраструктуры упаковать приложение и миграции в контейнеры. Для рабочего развёртывания нужны проверка личности, роли, TLS, резервные копии и восстановление, мониторинг и политика хранения. Подключение GPS отдельное. Контракты планировщика при замене хранилища сохраняются.

## Проверка

Автоматические проверки хранилища запускаются командой `python3 -m unittest discover -s tests -v`. Проверены конкурирующие записи одной ревизии, защита журнала и невозможность изменить закрытую смену. В браузере пройдены создание пустой смены, добавление КМ-77, передача работы, отмена дубля, приёмка, закрытие, открытие той же записи во второй сессии и проверка скачанного журнала.
