# Геоданные Петропавловска-Камчатского

[Машиночитаемый снимок](petropavlovsk.json) получен из OpenStreetMap 19 ноября 2026 года. © OpenStreetMap contributors, лицензия [ODbL](https://www.openstreetmap.org/copyright). Снимок охватывает пять прямоугольников между центром и северо-западными районами. Крайние части города и некоторые связи через границы покрытия требуют дополнительных выгрузок.

## Формат

| Поле | Содержимое |
| --- | --- |
| `bounds` | Прямоугольники каждого запроса `[west, south, east, north]` в WGS 84. |
| `nodes` | OSM ID узла → `[longitude, latitude]`. Всего 63 042 узла во всех слоях, включая здания. |
| `ways` | OSM ID линии → `[node_ids, tags]`. Всего 3 537 `highway`-линий, включая 845 пешеходных и велосипедных. Это линии OSM, одна улица может состоять из многих линий. |
| `land` | Контуры зданий, зелёные зоны, берег и вода для подложки. |
| `points` | 396 точек, включая 130 остановок, 225 переходов и 41 объект медицины или образования. |
| `turn_restrictions` | 193 отношения ограничений манёвров. У 6 отношений хотя бы одна линия выходит за доступную сеть. |

В JSON сохраняются идентификаторы, порядок узлов и исходные дорожные атрибуты, если они есть. Демонстрационные треки хранятся отдельно. У 2 692 линий-кандидатов для автомобильной сети заполнена ширина только у 5, уклон только у 7, покрытие у 754. Допустимость проезда спецтехники определим после сверки. Значения могут требовать полевой проверки даже там, где OSM-теги заполнены.

## Воспроизведение импорта

Источник — `https://api.openstreetmap.org/api/0.6/map?bbox=west,south,east,north`. Скачать XML для каждого прямоугольника и передать все файлы одной команде из корня проекта:

```sh
python3 demo/import_osm.py /path/to/extracts/*.osm
```

Прямоугольники использованной выгрузки:

```text
158.625,53.008,158.669,53.040
158.619,53.040,158.669,53.069
158.591,53.066,158.635,53.095
158.573,53.094,158.618,53.119
158.583,53.036,158.625,53.067
```

Импорт создаёт `data/petropavlovsk.json` для обработки и `demo/petropavlovsk.js` для браузера. Так карта открывается локально без сервера и ключей. Данные участников редактирования и история правок в производный снимок не попадают.

## Что нужно для следующего слоя

- Для дорожного графа разрезать линии в общих узлах, учесть направления, ограничения поворотов и ограничения по доступу. Проверить связность, неполные отношения на краях и выборочные эталонные пути. Пешеходные связи хранить отдельным слоем.
- Для зимнего профиля добавить рельеф, ширину и опасные места, допустимость для типов техники, зоны ответственности, обязательные приоритеты, официальные базы и места вывоза. Для живого экрана потребуется муниципальная телеметрия и способ подтверждать фактическую очистку.
- Яндекс и 2ГИС пригодны для проверки или получения времени проезда и трафика после оценки местного покрытия и условий доступа. OSRM и Valhalla кандидаты на локальную маршрутизацию. Транспортные API не содержат полного муниципального профиля зимнего обслуживания. Выбор движка нужен после проверки графа и сценария, которому он должен служить.
